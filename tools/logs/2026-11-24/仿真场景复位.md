# 仿真场景复位

客户端仿真页的「复位」先关闭仿真进程的标准输入，等原进程正常关闭 Gazebo、Godot 和 ROS 后，再加载初始场地。复位期间清空旧画面，禁用任务按钮，等新画面恢复后可运行下一轮。

- Windows 用 `tools/laptop_server/build.ps1` 的 Qt 6.12.0 和 MinGW 配置完成编译。旧客户端正在运行，构建脚本复制时遇到文件占用。把旧 EXE 移到 `build/` 备份后安装新版，`dist/GongchuangClient.exe` 与编译输出 SHA-256 一致。
- `build/reset-scene-smoke` 用 Qt 实际按钮和独立子进程连续复位两次，验证每次旧进程退出后才启动下一次。
- `wsl -d Ubuntu-22.04 -- python3 build/test-scene-reset-world.py` 在独立 Gazebo 分区试跑完整场地。车先移动约 0.99 m，20 块物块移位。重开场地后，车和全部物块的平面位置与第一次启动的最大差值约 0.008 mm。原客户端会话继续运行。
