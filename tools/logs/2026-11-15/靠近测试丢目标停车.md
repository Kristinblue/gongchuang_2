# 靠近测试：丢目标时补发一次停车

- 时间：2026-11-15 14:28（14:40 补命令位常量）
- 改动文件：
  - `src/tests_pkg/tests_pkg/nodes/approach_test_node.py`
  - `src/tests_pkg/README.md`
  - `src/robot_interfaces/msg/Command.msg`

## 为什么改

下位机 PID 会**保持最后一条 01（前后）/02（转向）指令**。原来的 `on_frame` 在找不到目标时直接 `return`，什么都不发，
视觉一丢目标，车会拿着上一帧的旧误差继续冲；`drive` 模式下只有「0.5 秒收不到新帧」的看门狗才停车，救不了这种情况。

## 改了什么

- 新增成员 `self.halted`（初始 `False`），表示「这次丢失是否已经发过停车」。
- `on_frame` 里 `target is None` 时：只有 `halted` 还是 `False` 才发一条 `self.send(Command.STOP, 0)`，随后把 `halted` 置 `True`。
- 重新选到目标时把 `halted` 复位为 `False`，恢复逐帧发误差。
- 没有动 `self.active`：丢目标不停服务状态，目标重新出现后自动接着跑，不用再调 start。
- README 里「找不到目标就输出停车」改成说明「补发一次，同一次丢失只发一条」。

停车这条同时会进 `/approach_test/command`（调试）和 `/robot/command`（`drive` 或 `publish_motion` 打开时）。

## 命令位常量

原来节点里写的是 `self.send(6, 0)` 这种字面量，`Command.msg` 只有 `code` / `value` 两个字段，没定义 code 的取值。
现在在 `Command.msg` 里加了消息常量（只参与编译、不进串口帧，协议不变）：

```
uint8 HEARTBEAT=0  STRAIGHT=1  TURN=2  GRAB=3  CAMERA=4  TURN_ANGLE=5  STOP=6
```

Python 侧用 `Command.STOP`、`Command.TURN`、`Command.STRAIGHT`，C++ 侧对应 `robot_interfaces::msg::Command::STOP`。
生成出来的常量在 WSL 里验证过：`Command.STOP == 6`。

```bash
mkdir -p /tmp/ri_ws/src && cp -r src/robot_interfaces /tmp/ri_ws/src/
cd /tmp/ri_ws && source /opt/ros/humble/setup.bash
colcon build --packages-select robot_interfaces
source install/setup.bash
python3 -c "from robot_interfaces.msg import Command; print(Command.STOP)"
rm -rf /tmp/ri_ws
```

## 备注

`serial_node` 自己还有一层看门狗：收到 01/02 后 750 ms 没有新动作或心跳就会补一帧停车。
靠近测试每帧都发 01/02，所以正常情况下不会触发；丢目标这条停车只是把停车时机提前到「这一帧就看见目标没了」。
