## 把场地改成单个绿块

仿真的物块有两套：物理在 `worlds/gripper_manual.sdf`，画面在 `native_render/assets/field.glb`。
只改 SDF 会出现「物理没了、画面还在」，所以两边都要动，写成 `tools/sim/field.py`：

```bash
python tools/sim/field.py one-green          # 删掉 19 个物块，只留 block_green_01
python tools/sim/stream.py --only-block block_green_01
python tools/sim/field.py restore            # 还原
```

- SDF 用正则删 `<model name="block_*">`，保留 `block_green_01`，位置不动，和画面里的绿块对齐。
- Godot 侧在 `gripper_stream.gd` 里插了一段 `GC_ONLY_BLOCK` 开关，`stream.py --only-block` 设环境变量，只显示这个块。
- 两个文件都先备份成 `.bak`，`restore` 拷回去。

改的时候踩了一个坑：SDF 的 `<pose>` 要 6 个数，我一开始只写了 `0 0 0.001`，
Gazebo 直接报 `//pose must have 6 values`，整个世界加载失败。

## 接近结果

场地只剩一个绿块，接假 STM32（`--sim-host 172.27.176.1`）和 `color:=green` 启动：

- `/approach_test/start` 返回 success；
- 车从远处向绿块开，误差 `01` 一直在 -180 附近（目标还远），`02` 在 ±100 里调整方向；
- 最后开到绿块前，块占满画面下方，转向误差收敛到 0 附近；
- 横向上有点过冲，最后块偏画面左下；停车距离也比 `y0=550` 的近。
  这是假板的转向/速度增益和 5 fps 控制延迟导致的，不是链路问题，要更稳就调 `tools/stm32_sim.py` 里的增益。
