## 热点复查

用户说密码是 `11111110`，之前一直没改过。实测：

- 用 `11111110` 重新配置后，派能激活连接并拿到 DHCP 地址 `192.168.137.207`；
- 但 5～10 秒后被断开：`CTRL-EVENT-DISCONNECTED ... reason=0`，
  之后停在 `connecting (need authentication)`，`iw dev wlan1 link` 是 Not connected，
  `/sys/class/net/wlan1/carrier` 为 0，路由变成 `linkdown`，ARP `INCOMPLETE`；
- 关掉 PMF（`wifi-sec.pmf 0`）没用；
- 关掉 Wi-Fi 省电（`802-11-wireless.powersave 2`）能多撑一会儿（约 20 秒），但还是会掉；
- 静态 IP 按用户要求已改回 DHCP。

判断：派能关联、能过四步握手、能拿 DHCP，但 AP 很快把客户端踢掉，数据面根本没通。
派是 Realtek 8852BE，电脑热点是 Realtek 8852CE，两边同厂同时代的组合容易出这种问题；
也不排除 Windows 移动热点本身没有真正桥接。

怎么确认责任：

- 让派连一次手机热点，如果能稳住，就是电脑热点的问题；
- 如果手机热点也掉，就是派这块网卡/驱动的问题。

暂时可靠的是有线：`ssh pio-wired`（192.168.60.2）一直正常。
另外 `pio` 别名写死 `192.168.137.247`，DHCP 一般给别的地址，这个别名本身也要改。

## 下拉框和终端延迟

- 下拉框弹出后白底白字、看不到选项：样式里只设了背景和选中色，没设列表文字颜色。
  加了 `QComboBox QAbstractItemView { color: #1f2328; }` 和 `::item` 规则。
- 终端延迟高：原来每敲一条命令都新开一个 `ssh`，连接加认证要几百毫秒。
  Windows 的 OpenSSH 不支持 `ControlMaster`（报 `getsockname failed: Not a socket`），
  改成连接时开一个常驻 `ssh -T` 会话，命令直接写到它的 stdin，
  用 `printf '\n__GC_DONE__%s\n' $?` 当结束标记；开头的 MOTD 用 `__GC_READY__` 标记丢掉。
  现在一条命令基本只等一个网络往返。
- 常驻会话不是交互 tty，`Ctrl+C` 没法只中断子命令，按了会断开这次会话（点「连接」重连）。
