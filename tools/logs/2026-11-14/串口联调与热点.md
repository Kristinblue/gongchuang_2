# 2026-11-14 · 串口联调与热点排查

时间：17:20–17:35

## 串口联调（结论：双向都通）

用 `tools/stm32_sim.py` 的伪串口接 `serial_node`：

- `serial_node` 正常打开 `/dev/pts/4 115200`；
- `/robot/state`：`connected: true`、`team: red`（假板开机回 `01` 的反馈）；
- **下发**：发 `04=40`，假板日志出现 `相机(04) = 40`，`/robot/state` 变成 `camera_deg: 40`、`camera_known: true`；
- **回传**：发 `05=20`，假板转完回 `05=1`，`/robot/feedback` 收到 `(5, 1)`。

注意两点：

- `ros2 topic pub` 要等图建好（`ros2 topic info /robot/command` 有 1 个订阅）再发，刚 launch 完就发会等不到订阅。
- `05` 转角期间要发心跳（`code 0`）或用小角度，否则 `serial_node` 的 750ms 看门狗会补 `06` 停车。

## 接近增益

按要求没有继续细调。`tools/stm32_sim.py` 加了参数和死区，默认值改成更稳的一组：

```
--speed-gain 0.00015  --turn-gain 0.0008
--speed-limit 0.1     --turn-limit 0.5
--speed-deadband 15   --turn-deadband 12
```

单绿块在远处很小，YOLO 会闪（`observed=False`），接近节点没目标就发 `06` 停，
所以停不准主要是检测稳定性，不是串口。要精调得先把目标检测稳住。

## 热点为什么连不上

- 派这边：`wlan1` 是 `disconnected`，但保存了 `kristin` 配置，`autoconnect=yes`、`ipv4.method=auto`；
  扫描也**扫不到 kristin**，说明不是派的问题。
- 电脑这边：WLAN 连着 `NJUPT-CMCC`，但「本地连接* 10」没有 `192.168.137.1`，
  说明**移动热点根本没开**。
- 最可能的原因：Windows 11 移动热点默认「没有设备连接时自动关闭」，这段时间一直用网线，热点就自己关了。
- 试过用 WinRT 接口（`NetworkOperatorTetheringManager`）从命令行开，`StartTetheringAsync` 在这台机器上卡住，
  所以还是手动开：设置 → 网络和 Internet → 移动热点 → 打开。
- 开了之后派会自动连 `kristin`。注意 SSH 别名 `pio` 写死的是 `192.168.137.247`，
  如果 DHCP 分了别的地址，`ssh -G pio` 看一眼再改 `~/.ssh/config`，或者直接 `ssh orangepi@新地址`。
