# 2026-11-14 · 仿真视频流与假 STM32

时间：16:35–17:05

## 做了什么

1. 撤掉 `src/sim_pkg`。它是电脑上用的东西，进 `src` 会被带去香橙派，不划算。
2. 仿真画面改走**现成的 http 摄像头源**，和网络摄像头同一条路，ROS 侧一行不用加：
   - `tools/sim/stream.py`（Windows）：启动仿真后端，把相机画面推成 MJPEG，`http://0.0.0.0:8090/video`。
   - `tools/sim/run_sim.sh`（WSL）：用 `ip route` 取 Windows 主机地址，自动填 `camera_url`，不用手抄 IP。
3. `tools/stm32_sim.py`：伪串口假 STM32，没有下位机也能验证串口和动作链路。

```text
Windows  tools/sim/stream.py   仿真后端 → MJPEG:8090
                                     │
WSL      camera_node(source:=http) ←─┘
         → inference_node → perception_node → approach_test_node
         → /robot/command → serial_node → /dev/pts/N → tools/stm32_sim.py
```

- 6 个包编译通过（`sim_pkg` 去掉后回到 6 个）。

  `/vision/objects` 有 9 个框（orange/blue/green/black，0.74～0.93）。

- 单独发命令：`02=50` 后假板角速度 -0.06，`04=40` 相机角变 40，`05=90` 转约 92° 后回 `05=1`。

## 踩到的坑

- WSL 访问 Windows 服务要用网关地址，`/etc/resolv.conf` 里的 10.255.255.254 不是主机，会 connection refused；
  用 `ip route show default` 的网关（这次是 172.27.176.1）。
- 假 STM32 不能一直占着 pty 的 slave 端：`serial_node` 要 `TIOCEXCL` 独占，
  上一轮被强杀后独占标志还在，重开就报「无法独占串口」。现在脚本拿到名字就关 slave，收到第一帧后再补发队伍帧。
- 强杀 `stream.py` 不会走 `backend.close()`，WSL 里会留下 `ign gazebo`，用 `ps` 找到 PID 再 `kill`。
- 帧率受仿真渲染限制，请求 10 fps 实际约 5 fps。

## 没做

- 仿真只给画面，假 STM32 也不驱动仿真里的车（车不动，画面静止）。
- 没上实车，没碰真实串口。
- 没有提交。
