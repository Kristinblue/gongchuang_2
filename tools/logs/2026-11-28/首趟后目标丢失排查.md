## 底边三点、裁切底色补足与同视角区内记忆（17:15–17:45）

用同一组 130 s 保存位姿连续做了三轮改进与复测，逐步消除已入区绿块的误选：

1. **底边三点外侧判断（`perception_node.py`）**：把原先检测框底边单中点包含判断改为 `near_safety_zone`，在框底边 `0.2 / 0.5 / 0.8` 处取三个采样点，并留按 720p 缩放的 `8 px` 边界容差——只有三点都明确在安全区轮廓外超过容差时才允许参与搜寻，贴边物块先跳过。单测见 `build/track-zone-check/check.py`。但实跑发现安全区紫框被画面边缘裁切时，仅靠可见紫框求凸包会把大片红区地面切在轮廓外，三点距轮廓可达 67～90 px，仍会重选绿块。
2. **裁切安全区的连通底色补足（`safety_detector.hpp` / `safety_detector.cpp` / `safety_detector_node.cpp`）**：仅在紫框贴近画面边缘（`margin < 3`）且已判出 `r_safety` / `b_safety` 时，查找与原紫框轮廓相交面积最大的同色地面连通域，合并求凸包存入 `object_polygon`，发给 `vision/safety_regions_raw` 专供物块过滤；导航投放使用的 `vision/safety_detection` 仍保持原 `polygon` 不变。单测见 `build/track-zone-check/check.cpp`，并同步重编更新客户端 `tools/laptop_server/dist/GongchuangClient.exe`。复测正面朝向红区时已能排除该绿块，但右转搜寻、绿块移至画面左缘时，安全区短暂漏检或只剩右侧窄条，导致左缘几帧恢复为区外并再次触发锁定。
3. **同视角跟踪 ID 区内记忆（`perception_node.py`）**：在相机俯角稳定（`ready`）的同一视角下，用 `zone_ids` 记录已判定在安全区内的 `(name, id)`；右转过程中即使安全区轮廓短暂消失，只要同一跟踪 ID 未过期就保持 `in_safe_zone=true`，切换俯角、切换队伍或目标 ID 消失后自动清除。单测见 `build/track-zone-memory/check.py`。
