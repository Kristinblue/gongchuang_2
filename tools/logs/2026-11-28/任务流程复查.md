# 任务流程复查

项目入口是客户端「运行仿真任务」。任务节点收到新检测帧后，依次调用开局打散、搜寻追踪、抓取和投放。客户端从 JPEG 响应的 `X-Gongchuang-Vision` 读取阶段和画框信息。

| 环节 | 本次调整 |
| --- | --- |
| 搜寻 | 固定俯角下一圈搜寻后挪位。等新俯角对应的画面才选块。距离门槛独立于类别权重。转向缺反馈时停车重搜。 |
| 抓取 | 合爪后退等 07 到位。打散后有多个同类框时，按底边远近选一块并连续确认。 |
| 投放 | 定距移动等 07 到位。统一为绕开后停车重看安全区，删掉按仿真速度估算余量的预设路线。 |
| 界面 | 原图和识别结果左上角显示中文主阶段及子动作。 |

验证命令：

```powershell
cmake --build tools/laptop_server/build --parallel 2
wsl -e bash tools/build.sh
& D:/MySoftware/miniconda3/envs/yolov8/python.exe -X utf8 build/task-audit/live.py
```

第一次整场仿真完成搜寻、追踪、合爪、后退和单块复核，进入投放时遇到两次绕行。记录窗口结束时还在绕行。第一轮阶段保存在 `build/task-audit/first-stages.txt`。

第二次复现反复抬头低头。追踪视角的目标框底边在 719 px，低头后近处绿框底边在 573 px，远处同色框在 133 px。旧逻辑把两个都放进同一横向范围，因候选数为二放弃关联。修正后只查看近处候选，同一物块连续三帧才重新锁定。保留拒绝两个近处候选的行为。实际框坐标在 `build/task-audit/shot-8.headers` 和 `shot-3.headers`，整轮记录在 `build/task-audit/pitch-loop-stages.txt`。

回放和串口伪设备验证通过。旧的 11 月 26 日检查脚本还要求横向偏差 29 px 时不合爪，与当前放宽的爪口策略不一致。

第三轮跑了修正后的完整仿真入口。搜寻 → 追踪 → 两次按计划低头 → 合爪 → 按回包退车 → 单块复核 → 寻找安全区。中间没有返回搜寻。搬运中识别到约 31 cm 前方有物块，退车绕行时转向超时，补角前的短退也没有收到 07，最终闭爪停车。首趟实际投放和入区仍待验证。阶段和任务日志分别在 `build/task-audit/stages.txt` 与 `build/task-audit/live.log`。
